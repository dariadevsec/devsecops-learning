### Команды, которые я выучила

| Команда | Что делает |
| --- | --- |
| `pwd` | показывает, в какой папке я сейчас |
| `ls` | показывает, что лежит в папке |
| `ls -a` | показывает ещё и скрытые файлы (имя начинается с точки) |
| `cd папка` | заходит в папку |
| `cd ..` | выходит на уровень выше (пробел обязателен) |
| `mkdir имя` | создаёт папку |
| `cat файл` | показывает, что написано в файле |
| `file файл` | определяет тип файла (текст или данные) |
| `find` | ищет файлы по условиям (размер, владелец, тип) |
| `grep слово файл` | находит строки со словом |
| `sort` и `uniq -u` | сортирует строки и оставляет те, что встречаются один раз |
| `strings файл` | вытаскивает из файла читаемый текст |
| `base64 -d файл` | расшифровывает запись base64 |
| `ssh` | подключает к другому компьютеру через интернет |
| `exit` | выходит из подключения |
| `find . -type f` | ищет только файлы (без папок) в этой папке и вложенных |
| `echo "слово" > файл` | записывает слово в файл (`>>` дописывает в конец) |
| `base64 файл` | кодирует содержимое файла в base64, а с `-d` расшифровывает |

### Что я поняла
- Символ `\|` («труба») передаёт результат одной команды в другую
- Пробелы в имени файла нужно брать в кавычки
- Имя файла, которое начинается с дефиса, пишут с `./` перед ним
- Команда `2>/dev/null` прячет сообщения об ошибках
- Base64 это не защита, а просто другая запись текста
- Base64 всего лишь другой способ записи, в котором нельзя хранить пароли. Расшифровать может любой.

### Новые команды

| Команда | Что делает |
| --- | --- |
| `grep -c "слово" файл` | считает строки со словом, а не выводит их |
| `grep -i "слово" файл` | ищет без учёта регистра (error, Error, ERROR) |
| `whoami` | показывает, под каким пользователем я работаю |
| `ls -l` | показывает файлы вместе с правами, владельцем, размером и датой |

### Права доступа (r, w, x)

- `r` читать, `w` менять и удалять, `x` запускать
- Для файла `x` значит «можно запустить как программу»
- Для папки `x` значит «можно войти в папку»
- Права записаны тремя тройками: владелец, группа, все остальные
- Первый символ в `ls -l`: `-` это файл, `d` это папка
- Лишние права это частая дыра в безопасности

### Нашла сама
- `grep -c`: считает строки с совпадением (нашла в интернете после подсказки)

### Узнала от Claude и применила на практике
- `grep -i`: применила к своему файлу `server.log`
- Пробел в команде это разделитель, поэтому `cd..` без пробела не работает

### Узнала, но ещё не отрабатывала
- Настройки команд можно писать слитно: `-ci` вместо `-c -i`
- Русская «с» и латинская `c` это разные символы для терминала

### Где ошиблась
- В `echo ... > файл` первая команда не записалась из-за опечатки, и в файле оказалось на строку меньше
- Команда `uniq -u` без файла зависла и ждала ввода: выход через Ctrl+C
- Пробел в имени `my notes.txt` без кавычек: команда увидела два слова

### Зачем это нужно в работе
- `grep` и `sort | uniq` помогают находить в журналах сервера подозрительную активность
- `find` ищет забытые секреты и следы взлома
- Неправильные права на файл: одна из самых частых причин утечек
